## 1. 第一步：顺序表到底保存什么

线性表是逻辑概念：元素有先后顺序。顺序表是线性表的一种存储实现：元素依次放在连续的存储单元中。

“顺序存储”说的是存储位置连续，**不表示元素值已经从小到大排序**。`30 10 20` 同样可以存成顺序表。

```c
#define SQLIST_INIT_CAPACITY 100
typedef int ElemType;

typedef struct SqList
{
    ElemType *data;
    int length;
    int capacity;
} SqList;
```

字段分工：

| 字段 | 含义 | 例子 |
|---|---|---|
| data | 指向动态数组首元素的指针 | data[0] 保存第一个元素 |
| length | 当前有效元素数量 | 3 表示只有 data[0..2] 有效 |
| capacity | 当前已分配的元素格数 | 初始为 100，之后可以增大 |
| SQLIST_INIT_CAPACITY | 初始容量，不是最大容量 | 本版本从 100 开始 |

`typedef int ElemType` 给 int 起别名，便于看出它表示元素类型；本次所有输入输出和算法都按整数实现。以后若改为结构体，还要检查 printf 格式、相等/大小比较等代码，不能只改 typedef 就认为全部完成。

`typedef struct ... } SqList;` 给结构体类型起名，之后可以直接写 `SqList L;`。

举例：容量是 100，当前表为 `10 20 30`：

```text
数组下标       0    1    2    3   ...   99
有效元素      10   20   30   余下是未使用区域
接口位置       1    2    3
length = 3，容量 = 100
```

未使用区域仍然属于数组内存，但不属于当前顺序表的数据，不能把其中的值当作有效元素。

本项目统一：接口位置从 1 开始，数组下标从 0 开始。因此“第 i 个元素”位于 `data[i-1]`。

## 3. 第三步：先认清参数与返回值

先看三个典型接口：

```c
int SqListInit(SqList *L);
int SqListLength(const SqList *L);
int SqListGetElem(const SqList *L, int i, ElemType *outValue);
```

`SqList *L` 接收表变量的地址，函数可以修改原表。调用时写 `SqListInit(&L)`；函数内部用 `L->length` 访问字段。

`const SqList *L` 用在只查询的接口中，禁止通过这个指针修改表字段，例如 length、capacity 或 data 指针本身。它不会自动让 data 指向的数组深层只读，查询函数仍需遵守不修改元素的约定。C 语言同样支持 const，不是 C++ 专属语法。

`ElemType *outValue` 是输出参数，指向调用者用于接收结果的变量。例如：

```c
ElemType x;
if (SqListGetElem(&L, 2, &x) == SQLIST_OK)
{
    printf("%d\n", x);
}
```

函数可以同时返回成功状态，并通过 `*outValue` 交付数据。只有成功后才能使用刚取到的 x。

状态码：`SQLIST_OK` 为 1，`SQLIST_ERR` 为 0。判空/判满的 1/0 是“条件是否成立”；LocateElem 返回位置或 0；RemoveAll 返回删除数量。它们都是 int，但含义不同，读接口注释时要区分。

使用条件：先声明 `SqList L = {0};`，再检查 Init 返回成功，length 必须在 0..capacity 之间。输出参数应指向表外的有效整数变量；不要指向本表内部字段。Delete/PopBack 特别允许输出参数为 NULL，表示不需要被删值。不要写 `SqList L2 = L;` 来复制一个活表：这只复制指针，会共享数组并可能重复 free。需要独立副本，应初始化 L2，再用 Assign 复制数值。

## 4. 第四步：初始化、判空、判满、求长

接口：

```c
int SqListInit(SqList *L);
int SqListEmpty(const SqList *L);
int SqListFull(const SqList *L);
int SqListLength(const SqList *L);
int SqListCapacity(const SqList *L);
```

核心实现：

```c
int SqListInit(SqList *L)
{
    if (L == NULL || L->data != NULL)
    {
        return SQLIST_ERR;
    }
    return SqListReserve(L, SQLIST_INIT_CAPACITY);
}
```

`SqList L = {0}` 将 data 设为空指针、length 和 capacity 设为 0；Init 通过 Reserve 分配初始数组。`realloc(NULL, 正字节数)` 可以申请新内存。只初始化结构体，不必把整个数据数组清零。初始容量是常数 100，因此按本版本的初始规模分析为 O(1)。初始化可能分配失败，必须检查返回状态。

Empty 比较 length 与 0；Full 判断已有容量是否已被元素占满；Length 返回 length，Capacity 返回 capacity。Full 为 1 不代表永远不能插入，插入接口会先尝试扩容。长度由插删操作维护，容量由分配操作维护。

空表不等于 `L == NULL`：`L == NULL` 是没有传入有效表地址；空表有真实的表变量，只是 length 为 0。

使用：

```c
SqList L = {0};
if (SqListInit(&L) != SQLIST_OK)
{
    return 1;
}
printf("length = %d\n", SqListLength(&L));
/* 用完之后调用 SqListDestroy(&L) */
```

自测：初始化后 data[0] 能直接当作第一个元素输出吗？为什么？

### 4.1 新增核心接口：空间不足时动态扩容

```c
int SqListReserve(SqList *L, int minCapacity);
```

它保证至少能容纳 minCapacity 个元素，但不改变 length：

1. 若已有容量足够，直接成功，不分配、不搬动。
2. 若空间不足，计算新容量，通常按 100 → 200 → 400 → 800 翻倍。
3. 用 realloc 申请更大的数组。
4. 成功后更新 data 和 capacity，失败则保留原表。

例如 length=100、capacity=100 时尾插第 101 个值，先扩到 200，再写 data[100]，最后 length=101。容量增大不会自动产生新元素。

关键片段（newCapacity 的计算见 SqList.c）：

```c
ElemType *temp = realloc(L->data,
    (size_t)newCapacity * sizeof(*temp));
if (temp == NULL)
{
    return SQLIST_ERR;
}
L->data = temp;
L->capacity = newCapacity;
```

realloc 的第二个参数是字节数，所以用“元素个数 × 每个元素大小”。`sizeof(*temp)` 是一个 ElemType 的大小，不会实际解引用 temp。不要用 `sizeof(L->data)` 计算整个数组大小，那只是指针大小。

为什么先用 temp？若直接 `L->data = realloc(...)`，失败时 NULL 会覆盖原地址，造成内存泄漏。realloc 失败时原数组仍然有效；成功时旧内容保留到原大小与新大小的较小者，地址可能改变。成功后只使用更新过的 data，不要再访问扩容前保存的元素地址，也不要另外 free 旧指针。

代码用 `<limits.h>` 中的 INT_MAX 防止容量和 length+1 的整数溢出，也检查元素个数乘 sizeof 的字节数上限。接近上限时不再强行翻倍，而是按本次所需容量申请；超过可表示范围返回失败。

按位插入、PushBack、有序插入、Assign 都复用 Reserve。必须先确认扩容成功，再移动或写入元素，因此分配失败不会破坏原表。删除和 Clear 不自动缩容，避免反复分配。

连续尾插的均摊复杂度为 O(1)：虽然少数扩容需要搬动许多元素，但倍增使总搬动量与总插入量成正比；单次触发扩容的尾插最坏仍是 O(n)。

自测：length=100 时 Reserve 到 200 后 length 是多少？扩容后原来保存的 `&L.data[0]` 一定还能使用吗？

## 5. 第五步：遍历与输出

```c
void SqListPrint(const SqList *L);
```

只遍历有效区：

```c
for (int j = 0; j < L->length; ++j)
{
    printf("%d ", L->data[j]);
}
```

实际完整函数在元素之间输出空格，末尾换行。这里 j 是数组下标，所以从 0 开始，条件是 `< length`。

不能写 `j <= length`：它会多访问一个不属于有效区的元素，length==capacity 时甚至会越界。也不能遍历全部 capacity 个格子，把未使用格子的内容输出。

## 6. 第六步：按位取值与修改，O(1)

```c
int SqListGetElem(const SqList *L, int i, ElemType *outValue);
int SqListSetElem(SqList *L, int i, ElemType value);
```

先验证 `1 <= i <= length`，再访问 `data[i-1]`。Get 还要确认 outValue 非空；失败不覆盖输出变量。

取值关键语句：

```c
*outValue = L->data[i - 1];
```

修改关键语句：

```c
L->data[i - 1] = value;
```

数组可以直接定位下标，不需要沿链逐结点走，所以按位访问 O(1)。修改只替换数据，不改变 length、不移动其他元素。

## 7. 第七步：按值查找、前驱和后继

```c
int SqListLocateElem(const SqList *L, ElemType value);
int SqListPriorElem(const SqList *L, ElemType value, ElemType *outValue);
int SqListNextElem(const SqList *L, ElemType value, ElemType *outValue);
```

LocateElem 从 data[0] 开始逐个比较，找到后返回 `j+1`，没找到返回 0。因为有效位置从 1 开始，0 不会和合法位置冲突。

重复值时返回第一个匹配位置。例如 `5 8 8 9` 中查找 8，返回 2。

PriorElem 先 Locate，再取 `i-1` 位置；NextElem 先 Locate，再取 `i+1`。如果没找到，或者目标恰好在没有前驱/后继的边界，返回失败。因为要按值查找，最坏仍为 O(n)。

前驱/后继按“第一个匹配元素”定义，不是在所有重复元素中任意选择一个。

自测：`5 8 8 9` 中调用 NextElem 查 8，取得的是 8 还是 9？

## 8. 第八步：按位插入，核心是从后往前搬

```c
int SqListInsert(SqList *L, int i, ElemType value);
```

含义：插入后，新元素成为第 i 个。合法插入位置是 `1..length+1`；比取值范围多一个末尾位置。位置校验后，先 `SqListReserve(L, L->length+1)`；只有成功后才能右移、写新值。空间不足时会自动扩容，分配失败或数量达到整数上限才返回失败。

例如在 `10 20 30 40` 的第 2 个位置插入 15：

```text
原表：     10 20 30 40
搬动 40：  10 20 30 40 40
搬动 30：  10 20 30 30 40
搬动 20：  10 20 20 30 40
填入 15：  10 15 20 30 40
```

这里展示的是数组内的中间状态，在 length 增加前最后一格还不是有效表元素。

核心代码：

```c
for (int j = L->length; j >= i; --j)
{
    L->data[j] = L->data[j - 1];
}
L->data[i - 1] = value;
++L->length;
```

在这个循环中 j 是目标数组下标，j-1 是源下标。初始目标为 length，也就是原有效区后的第一格；结束时刚好搬走 data[i-1]。

必须从后往前，否则先将 20 覆盖到 30 的格子，随后再复制那个格子，就丢失了原来的 30。

当 i=length+1 时循环一次也不执行，直接写 data[length]，就是尾插。尾插接口复用它：

```c
return SqListInsert(L, L->length + 1, value);
```

头插需要移动 n 个元素，尾插移动 0 个，普通插入移动 n-i+1 个。最坏 O(n)；尾插不扩容时 O(1)，扩容时最坏 O(n)，连续尾插均摊 O(1)。

## 9. 第九步：按位删除，核心是从前往后搬

```c
int SqListDelete(SqList *L, int i, ElemType *outValue);
```

删除前先验证 `1 <= i <= length`，空表不能删；如需返回被删值，先保存 data[i-1]。

例如删去 `10 20 30 40` 的第 2 个元素：

```text
原表：     10 20 30 40
搬动 30：  10 30 30 40
搬动 40：  10 30 40 40
length--：有效表为 10 30 40
```

核心代码：

```c
for (int j = i; j < L->length; ++j)
{
    L->data[j - 1] = L->data[j];
}
--L->length;
```

这里 j 是源数组下标，j-1 是目标下标。删除第 i 个以后，原第 i+1 个元素的数组下标恰好为 i。

必须从前往后搬，否则从尾部先搬会覆盖尚未读出的前面元素。最后一格可能留下旧值，不影响正确性；它已经在有效区之外，不必额外清零。

使用：

```c
ElemType deleted;
if (SqListDelete(&L, 2, &deleted) == SQLIST_OK)
{
    printf("deleted = %d\n", deleted);
}
```

不需要返回删除值时传 NULL：

```c
SqListDelete(&L, 2, NULL);
```

尾删接口 Delete(L,length,outValue) 不搬动元素，O(1)。一般删除需要移动 n-i 个元素，最坏 O(n)。

自测：删掉唯一元素后 length 为多少？还需要 free data[0] 吗？

## 10. 第十步：批量建表与清空、销毁

```c
int SqListAssign(SqList *L, const ElemType a[], int n);
void SqListClear(SqList *L);
void SqListDestroy(SqList *L);
```

Assign 先预留至少 n 个格子，再将已有数组的 n 个值复制到 data[0..n-1]，最后设置 length=n。a 必须至少包含 n 个有效元素，且来自独立数组，不能引用本表 data 内部；否则扩容可能让输入指针失效。n=0 时允许 a=NULL。参数错误或分配失败时不覆盖原表。

```c
ElemType a[] = {10, 20, 30};
SqListAssign(&L, a, 3);
```

它复制的是数值，源数组后来改变不会自动改动表里的内容。你也可以在 main 中读入一个值，调用 PushBack 逐个建表；把输入输出留在调用层，接口本身负责数据操作。

Clear 的实现只是 `L->length=0`，O(1)。旧数值可能仍在数组中，但逻辑上表已经为空，之后可直接插入。

动态数组版的 Destroy 真正释放数组：

```c
free(L->data);
L->data = NULL;
L->length = 0;
L->capacity = 0;
```

Clear 保留指针与容量，可以直接插入复用；Destroy 把它们归零，之后应再次 Init 再使用。Destroy 允许重复调用，因为 free(NULL) 无操作，但不能重复释放非空的旧地址。

局部结构体 L 的存储随作用域结束自动回收，但它指向的动态数组不会自动 free，所以结束前必须 Destroy。不要直接手动 free(L.data) 后继续使用表，让销毁接口统一释放并重置字段；也不要 free(&L)。

## 12. 扩展二：删除全部指定值

```c
int SqListRemoveAll(SqList *L, ElemType value);
```

如果每找到一个值就调用 Delete，再从头开始扫描，最坏会达到 O(n²)。本实现使用两个整数下标 read 和 write：read 看原表，write 指向下一格应保留的位置。

```c
int write = 0;
for (int read = 0; read < oldLength; ++read)
{
    if (L->data[read] != value)
    {
        L->data[write] = L->data[read];
        ++write;
    }
}
L->length = write;
```

例如 `2 1 2 3 2` 删除全部 2：只把 1、3 写到前面，最终 length=2。整个过程中 write 不超过 read，因此不会提前覆盖还没读取的数据，保留元素的相对顺序也不变。

只扫描一次，时间 O(n)，辅助空间 O(1)。返回删除数量，不是成功状态：没找到返回 0，不代表操作故障。

自测：如果全部元素都等于目标值，write 最后是多少？

## 13. 扩展三：插入并保持有序

```c
int SqListInsertOrdered(SqList *L, ElemType value);
```

前提是原表已经非递减有序。它不自动排序，也不会为每次插入额外遍历检查有序性。无序表应使用普通 Insert，或由调用者先完成排序。

从尾部开始，遇到比新值大的元素就右移；找到不大于新值的元素后停下：

```c
int j = L->length - 1;
while (j >= 0 && L->data[j] > value)
{
    L->data[j + 1] = L->data[j];
    --j;
}
L->data[j + 1] = value;
++L->length;
```

`j>=0` 必须放在 && 左边。C 的短路规则让 j 为 -1 时不会继续读取 data[-1]。

使用 `>` 而不是 `>=`，会把新值放在已有同值元素之后。寻找位置与搬元素合成一趟循环，最坏 O(n)。即使用二分查找把定位减少到 O(log n)，搬元素仍可能 O(n)。

这和项目中“顺序表插入保持有序”的原题是同一思路，现在只是封装进了接口。

## 15. 知识点总结

顺序表把“数组存储”和“逻辑长度”组合起来；数组下标是存储位置，接口位置是题目中的第几个元素，两者差 1。插入先腾位置，删除先补空位，方向由避免覆盖尚未搬动的数据决定。每次成功插删才更新 length，失败必须保持原表不变。只操作 data[0..length-1] 有效区。

模块化中，头文件描述使用规则，源文件实现规则，main 负责调用、输入输出和验证。

## 17. 复杂度总结

令 n 为表长，C 为当前容量，i 为合法的接口位置。下表的 O(1) 辅助空间是算法局部变量；realloc 若需迁移数组，在分配器内部可能同时保留新旧内存，因此扩容峰值内存可以是 O(C)。

| 接口 | 时间复杂度 | 辅助空间 | 原因 |
|---|---|---|---|
| Init | O(1)，初始容量固定 | O(1) | 申请初始 100 格 |
| Empty / Full / Length / Capacity | O(1) | O(1) | 直接访问结构体字段 |
| Reserve | 无扩容 O(1)，扩容最坏 O(C) | 局部 O(1)，迁移峰值 O(C) | 可能迁移数组 |
| GetElem / SetElem | O(1) | O(1) | 直接访问 data[i-1] |
| Print | O(n) | O(1) | 遍历有效区 |
| LocateElem / PriorElem / NextElem | 最坏 O(n) | O(1) | 按值顺序查找 |
| Insert | 最坏 O(n) | 无扩容 O(1)，扩容可能 O(n) | 扩容后再移动元素 |
| PushBack | 均摊 O(1)，单次最坏 O(n) | 无扩容 O(1)，扩容可能 O(n) | 倍增扩容 |
| Delete | O(n-i+1)，最坏 O(n) | O(1) | 移动 n-i 个元素并更新长度 |
| PopBack | O(1) | O(1) | 删除尾部，无需搬动 |
| Assign | O(n) | 无扩容 O(1)，扩容可能 O(n) | 预留并复制 n 个值 |
| Clear | O(1) | O(1) | 保留内存，只重置长度 |
| Destroy | 按一次 free 操作计 O(1) | O(1) | 不逐元素释放，重置字段 |
| Reverse / RemoveAll | 最坏 O(n) | O(1) | 一次扫描或成对交换 |
| InsertOrdered | 最坏 O(n) | 无扩容 O(1)，扩容可能 O(n) | 扩容后扫描并右移 |

在等概率插入位置下，平均移动 n/2 个元素；等概率删除位置下，平均移动 (n-1)/2 个，平均时间仍为 O(n)。

动态数组占用 O(C) 存储空间，结构体本身占固定空间。Clear 和删除不自动缩容，所以容量未必接近当前 n；如果曾经存很多值，清空后仍保留大容量。Clear 只是逻辑删除，不能保证旧数据被安全擦除。
