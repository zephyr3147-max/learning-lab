## 1. 第一课：栈限制在哪一端操作？

普通线性表可以按位置插入删除；栈只允许在栈顶插入和删除。

~~~text
入栈 10、20、30：

栈顶 → 30  ← 下一次出栈
       20
栈底 → 10

连续出栈：30、20、10
~~~

这叫后进先出，LIFO。它限制的是操作方式，不限制必须用数组还是链表存储。
栈不是“只能保存一个元素”，而是只能从一端取放。

本阶段练习：入栈 1、2，出栈一次，再入栈 3；全部出栈会得到什么顺序？

## 2. 动态顺序栈：size 不是 top

~~~c
typedef struct
{
    ElemType *data;
    size_t size;
    size_t capacity;
} Stack;
~~~

data 指向 malloc 申请的数组；size 是有效元素数；capacity 是可存储元素数。

| 含义 | 考试简版 | 动态模块版 |
| --- | --- | --- |
| 空栈 | top == -1 | size == 0 |
| 栈顶下标 | top | size - 1（非空时） |
| 元素数 | top + 1 | size |
| 存储 | 固定数组 | 动态数组 |
| 容量不足 | 入栈失败 | 尝试扩容，失败才返回 0 |

size_t 是标准库用于表示对象大小、数组长度的无符号整数类型。
打印它用 %zu；它不能表示 -1，所以不能把动态版的 size 设为 -1。
倒序循环写 i>0，访问 i-1，不写无符号 i>=0。

初始化：

~~~c
Stack S = {0};
if (!StackInit(&S, 2))
{
    return 1;
}
~~~

{0} 将三个字段初始化为零/空指针，避免读取未初始化指针。
S 是结构体，&S 是结构体地址；Init 修改 S 的字段，不需要 Stack **。
数组地址存入 S.data；不是把整个结构体本身 malloc 出来。

接口：

~~~c
int StackInit(Stack *S, size_t capacity);
int StackEmpty(const Stack *S);
size_t StackLength(const Stack *S);
int StackPeek(const Stack *S, ElemType *e);
~~~

- Init：capacity 必须大于 0，重复初始化失败，分配失败不改对象。
- Empty：判断 size==0；NULL 在本模块中不是有效的空容器。
- Length：直接返回 size，O(1)。
- Peek：读取 data[size-1]，不改 size；空栈或输出指针 NULL 时失败。
- const 用来表达查询接口不应修改结构体，但不是动态数组的深度只读保证。

所有接口要求对象及内部状态合法。不能手工把 capacity 改成 0、size 改成超过容量的数。
失败时输出参数不变，只在返回成功时使用输出值。

## 3. 入栈、出栈：真正删除的是逻辑位置

~~~c
int StackPush(Stack *S, ElemType e);
int StackPop(Stack *S, ElemType *e);
~~~

不考虑扩容时，入栈核心是：

~~~c
S->data[S->size] = e;
++S->size;
~~~

这里先存后增，因为 size 指向下一次写入的下标。
考试版先 ++top 再存，是因为 top 指向已有栈顶。两种写法都正确，但必须符合各自约定。

出栈先检查 size>0，再读取 data[size-1]，最后 --size。
Pop 的 e 可以为 NULL，表示只删除、不取值。

出栈不需要把旧数组位置清零；size 的改变就能把它排除出有效数据区。
下一次入栈会覆盖该位置。打印有效元素时不能遍历到 capacity。

~~~c
ElemType value;
if (StackPop(&S, &value))
{
    printf("%d\n", value);
}
~~~

练习：size=3 时，Push 写哪个下标？Pop 读哪个下标？

## 4. 扩容与批量入栈

~~~c
int StackReserve(Stack *S, size_t capacity);
int StackPushMany(Stack *S, const ElemType a[], size_t n);
~~~

Reserve 请求“至少这么多容量”，不是增加这么多，也不是改变长度。
请求不超过当前容量时成功但不操作；不主动缩容。

扩容过程：

1. 计算新容量，避免元素数量或字节数溢出。
2. malloc 申请新数组。
3. 失败立即返回 0，旧指针、长度、容量都保留。
4. 把已有 size 个元素复制到新数组。
5. 释放旧数组，提交新地址和新容量。

本实现使用 malloc + memcpy + free，而不是直接覆盖原指针调用 realloc。
这样步骤更容易看清；realloc 也可以实现，但必须先用临时指针接收结果，失败不能丢失原数组。

自动入栈容量不足时通常倍增：2 → 4 → 8 → 16。
接近可表示的最大容量时，源码改用实际所需容量，并检查 SIZE_MAX/sizeof(ElemType)。

一次扩容需要复制旧元素，单次 Push 最坏 O(n)。
容量倍增时，一串入栈操作的平均摊销成本为 O(1)，不能说每一次都保证 O(1)。
本版本 Pop 不缩容，避免反复出入栈造成频繁分配。

批量入栈示例：

~~~c
ElemType a[] = {10, 20, 30};
if (!StackPushMany(&S, a, 3))
{
    StackDestroy(&S);
    return 1;
}
~~~

10 先入，30 最后入，之后栈顶是 30。
批量操作先一次性保证容量，申请失败不会只插入前面一部分。
n=0 允许 a=NULL。a 必须是有效外部数组，不能传 S.data 内部地址，因为扩容可能使旧地址失效。

练习：容量 4、长度 4，再入一个值后，通常新容量和新长度分别是多少？

## 5. 清空、销毁、遍历

~~~c
void StackClear(Stack *S);
void StackDestroy(Stack *S);
void StackPrint(const Stack *S);
~~~

| 接口 | 动作 | 后续使用 |
| --- | --- | --- |
| Clear | size=0，保留数组与容量 | 可直接 Push |
| Destroy | free(data)，三个字段清零 | 再次 Init 后使用 |
| Print | 栈顶到栈底打印 | 不改变 size |

Destroy 接收 Stack *，将 S.data 置空即可；外部 S 是栈上结构体，不要 free(&S)。
重复 Destroy 安全，但其他保存的数组地址在释放后仍然是悬空指针，不得访问。
不要写 Stack B=S 再把 B 当独立副本销毁，那只是共享同一块 data。

### 最小模块调用示例

~~~c
#include "Stack.h"
#include <stdio.h>

int main(void)
{
    Stack S = {0};
    if (!StackInit(&S, 2))
    {
        return 1;
    }
    if (!StackPush(&S, 10) || !StackPush(&S, 20))
    {
        StackDestroy(&S);
        return 1;
    }
    ElemType e;
    if (StackPeek(&S, &e))
    {
        printf("top: %d\n", e);
    }
    while (StackPop(&S, &e))
    {
        printf("%d\n", e);
    }
    StackDestroy(&S);
    return 0;
}
~~~

若采用这个 main，应替换或另存 test.c，不要与原 test.c 同时链接。

## 6. 链栈：直接用单链表头插、头删

~~~c
typedef struct StackNode
{
    ElemType data;
    struct StackNode *next;
} StackNode;

typedef struct
{
    StackNode *top;
    size_t size;
} LinkStack;
~~~

本版不带额外头结点，top 就指向数据栈顶，空栈 top=NULL。
这与之前带头单链表的“头结点始终保留”约定不同。

~~~text
top → [30] → [20] → [10] → NULL
~~~

接口：

~~~c
int LinkStackInit(LinkStack *S);
int LinkStackEmpty(const LinkStack *S);
size_t LinkStackLength(const LinkStack *S);
int LinkStackPeek(const LinkStack *S, ElemType *e);
int LinkStackPush(LinkStack *S, ElemType e);
int LinkStackPop(LinkStack *S, ElemType *e);
void LinkStackClear(LinkStack *S);
void LinkStackDestroy(LinkStack *S);
void LinkStackPrint(const LinkStack *S);
~~~

先 LinkStack L={0}，再 Init(&L)。Init 不分配头结点，仅检查空对象，非空时不能重新初始化。

入栈：申请 p → 填 data → p->next=S->top → S->top=p → size++。
出栈：保存旧 top → 读取值 → top=旧 top->next → free 旧 top → size--。
不要 free 后再读 next。

链栈每次入栈申请一个结点，失败保持原栈；每次出栈释放一个结点。
链栈没有固定容量“满栈”，但仍可能因为内存不足或长度溢出而入栈失败。

Clear 与 Destroy 在本版动作相同：释放所有结点并恢复空栈，没有单独的动态头结点。
都可再次 Push，不必重新申请数组。非空时清理时间 O(n)，不能与顺序栈 Clear 的 O(1) 混淆。

## 7. 复杂度、应用与章节练习

| 操作 | 动态顺序栈 | 链栈 |
| --- | --- | --- |
| 初始化、判空、求长、取栈顶 | O(1)，不计分配器内部成本 | O(1) |
| 入栈 | 均摊 O(1)，单次最坏 O(n) | O(1)，不计分配器内部成本 |
| 出栈 | O(1) | O(1) |
| Reserve | 无搬迁 O(1)，搬迁 O(n) | 不需要 |
| 批量入 k 个 | 无扩容 O(k)，扩容 O(n+k) | 可循环 Push，O(k) |
| 清空 | O(1) | O(n) |
| 销毁 | O(1)，一次 free | O(n) |
| 遍历输出 | O(n) | O(n) |

顺序栈存储 O(capacity)；链栈存储 O(n)，每个结点多一个指针。
扩容期间旧数组和新数组同时存在，有 O(n) 级临时存储；其他普通操作辅助空间 O(1)。

应用：括号匹配、表达式解析、DFS、撤销、把输入逆序输出。
例如括号匹配：遇左括号 Push；遇右括号取顶并比对类型，再 Pop；结束时必须为空。
本模块保存 int，字符可转为整数用于练习；通用元素类型和 C++ 模板留到后续。

### 总结与 C/C++ 对比

栈是后进先出；顺序栈用长度维护有效区；链栈用单链表头部作为栈顶。
扩容保护旧数据；清空与销毁是否释放存储取决于具体实现。

| C 本章 | C++ 后续 |
| --- | --- |
| struct + 显式函数调用 | class 封装 |
| 手动 Init/Destroy、malloc/free | 构造/析构、RAII |
| ElemType 固定为 int | 模板支持不同元素类型 |
| 自定义栈 | std::stack 适配器（pop 不返回值） |
