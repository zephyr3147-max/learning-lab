## 第一课：一个结点为什么需要两个指针

本章固定约定：空树高度为 0，根在第 1 层，只有一个结点的树高度为 1；高度按层数计。部分资料按边数计，做题前先核对。

```text
        A
       / \
      B   C
     / \   \
    D   E   F
```

一棵非空二叉树由根结点、左子树、右子树组成。左右位置有区别：只有左孩子和只有右孩子是两种形态。

```c
typedef struct BiTNode
{
    char data;
    struct BiTNode* lchild;
    struct BiTNode* rchild;
} BiTNode;
```

`data` 保存本结点的数据；`lchild`、`rchild` 保存左右孩子的地址，没有孩子就保存 `NULL`。与单链表的一个 `next` 相比，这里有两个分支。

结构体内部使用 `struct BiTNode*`，因为末尾的 typedef 别名在此处还没声明完成。不能直接把两个孩子写成结构体对象，否则会要求无穷嵌套的存储空间。

```text
tree ──→ [ A | lchild | rchild ]
                 │        │
                 ▼        ▼
             [ B ... ] [ C ... ]
```

`tree` 是根指针变量；`*tree` 是根结点；`tree->lchild` 是根的左孩子指针。根指针变量不是另外分配的头结点，本模块不设置头结点。

先做练习：上图有几个叶子？`tree->lchild->rchild->data` 对应哪个字母？从空树出发能否直接求这个表达式？先画出每一步指向哪里。

## 第二课：三种遍历只差访问根的位置

| 遍历 | 顺序 | 示例结果 |
| --- | --- | --- |
| 先序 | 根、左、右 | ABDECF |
| 中序 | 左、根、右 | DBEACF |
| 后序 | 左、右、根 | DEBFCA |
| 层序 | 从上到下，同层从左到右 | ABCDEF |

递归先检查空指针。以中序为例：

```c
void BTInOrder(const BiTNode* tree, BTVisit visit)
{
    if (tree == NULL || visit == NULL)
    {
        return;
    }
    BTInOrder(tree->lchild, visit);
    visit(tree->data);
    BTInOrder(tree->rchild, visit);
}
```

递归进入左子树时，当前函数还没结束；它在调用栈里等待。左子树处理完才回到当前结点，再进入右子树。可以给每次调用写出“处理的根是谁”和“下一句在哪”，不要把函数返回误认为整棵树遍历结束。

`BTVisit` 是 C 的函数指针类型，定义为 `typedef void (*BTVisit)(char value);`：它指向“接收一个 char、无返回值”的函数。调用者传入函数名即可；`visit(tree->data)` 就是调用这个函数。这样同一遍历可用于打印或收集结果。初次阅读可把它理解成“访问这个结点”，考试版直接使用 `putchar`，无需先背函数指针。

这里的 `const BiTNode*` 表示该函数通过此指针只读当前结点；不能理解为 C 自动保证整棵对象图都不可修改。所有遍历回调都必须遵守不修改树结构的约定。

练习：手画 `BTInOrder(A)` 的调用过程，标出 D 被访问后返回哪一层。再只移动访问根的那一句，得到先序和后序。

## 第三课：把大问题拆成左右子树

| 任务 | 空树返回 | 非空树递推 |
| --- | --- | --- |
| 结点数 | 0 | 1 + 左结点数 + 右结点数 |
| 叶子数 | 0 | 左右都空返回 1，否则左右叶子数相加 |
| 树高 | 0 | 1 + max(左高, 右高) |

```c
size_t BTHeight(const BiTNode* tree)
{
    if (tree == NULL)
    {
        return 0;
    }
    size_t left = BTHeight(tree->lchild);
    size_t right = BTHeight(tree->rchild);
    return 1 + (left > right ? left : right);
}
```

`size_t` 是用于大小和计数的无符号整数类型，输出用 `%zu`，不能拿它表示 -1。先各算一次子树高度，再比较，避免在条件表达式中反复计算同一子树。

查找 `BTFind` 按先序搜索，重复值返回第一个匹配结点，未找到返回 `NULL`。使用结果前必须判空。查找所得指针只是借用；销毁原树后它就失效。

练习：树高为什么取 max，而结点数用加法？只剩一条长度为 n 的链时，树高是多少？

## 第四课：先序建树与二级指针

只知道 `ABDECF` 不能确定普通二叉树的形状。给每一个空孩子加入 `#` 后，先序串变成：

```text
ABD##E##C#F##
A(B(D(#,#), E(#,#)), C(#, F(#,#)))
```

`#` 表示空树，不创建结点，因此本实现不能把 `#` 当数据。模块输入是一整个字符串，不跳过空白；空树串为 `"#"`，空字符串不是合法编码。每创建一个结点都要继续读取它的左、右子树，包括空标记。

```c
BiTNode* tree = NULL;
if (!BTCreate(&tree, "ABD##E##C#F##"))
{
    return 1;
}
BTDestroy(&tree);
```

`tree` 的类型是 `BiTNode*`；`&tree` 的类型是 `BiTNode**`。当函数需要让调用者的根指针指向新结点时，要传入根指针变量的地址。

```text
调用者： tree = NULL
           ▲
           │ *参数就是调用者的 tree
函数内： BiTNode** 参数 = &tree

*参数 = 新结点地址  →  调用者的 tree 随之改变
```

只修改 `BiTNode*` 形参本身，改变的是指针副本；通过这个指针修改已有结点字段，则可以影响原结点。两种操作需要区分。

`ReadNode` 还接收 `const char** cursor`，用于推进外部的读串位置。申请失败或编码不完整会释放已经创建的部分；串末有多余内容也会失败。目标必须先置 `NULL`，不能把已有树直接覆盖掉。

练习：`A##`、`A#`、`A###` 哪些合法？为什么传 `&tree->lchild` 能设置某个结点的左孩子？

## 第五课：后序销毁、镜像与复制

销毁顺序：销毁左子树 → 销毁右子树 → 释放根 → 将根指针置空。必须先读取并处理孩子，再释放父结点。`free` 后不能继续从父结点读取孩子指针。

`BTDestroy(&tree)` 最后使调用者的 `tree == NULL`。对这棵树重复调用安全；但先前保存的其他结点指针仍会悬空，函数不会自动找到并清空所有别名。

镜像 `BTMirror`：交换每个结点的左右孩子指针，再递归处理两个子树。只交换根的两个孩子，只改变了第一层，不能完成整棵树镜像。

深拷贝 `BTCopy`：每个源结点都对应一个新申请的结点。`copy = tree` 只是两个指针指向同一棵树；直接复制结构体也会共享孩子，不是深拷贝。副本初始必须为 `NULL`，不能把源树内部字段作为副本输出位置。

练习：画出 `copy = tree` 与深拷贝后的地址关系。销毁原树后，哪种情况下副本仍然有效？

## 第六课：队列与栈把前面的章节连接起来

层序遍历：根入队 → 只要队列非空就取队头访问 → 左孩子非空则入队 → 右孩子非空则入队。

本模块先求结点数 n，再申请 n 个结点指针的数组作队列；每个非空结点只入队一次，不设置固定的 100 个结点上限。`front` 指向下一次出队位置，`rear` 指向下一次入队位置；这里是单次遍历用的线性队列，不是循环队列。

队列保存地址，不复制结点；只释放队列数组，不释放树。申请失败返回 0；成功返回 1。空树配合有效回调也算成功。此实现的队列分配空间为 O(n)，不能直接写成 O(最大层宽)。

非递归中序作为提高练习：

```text
p = 根
只要 p 非空或栈非空：
    只要 p 非空：p 入栈；p = p 的左孩子
    出栈到 p；访问 p
    p = p 的右孩子
```

提示：外层条件必须是“或”，否则在向左走到空指针时会提前终止。栈存结点指针，先不要急着写完整答案，手工模拟示例树。
