## 1. 第一课：队头删除、队尾插入

~~~text
出队方向 ← 队头 [10] [20] [30] 队尾 ← 新元素入队
~~~

先入队的先出队，FIFO。
10、20、30 顺序入队，出队仍是 10、20、30；与栈的 30、20、10 相反。

限制的是操作顺序，不是存储方式。队列既可以用数组，也可以用链表。
常见应用是 BFS、层序遍历、任务等待与缓冲，不是“只能存两个元素”。

本阶段练习：入队 1、2，出队一个，再入队 3；全部出队是什么顺序？

## 2. 动态循环队列：保存 size，不再牺牲单元

~~~c
typedef struct
{
    ElemType *data;
    size_t front;
    size_t size;
    size_t capacity;
} Queue;
~~~

data 为动态数组；front 为队头下标；size 为当前元素数；capacity 为容量。
本版没有单独保存 rear，可从 front 和 size 计算下一次写入位置。

| 约定 | 考试留空单元版 | 进阶 size 版 |
| --- | --- | --- |
| 判空 | front==rear | size==0 |
| 已用满容量 | (rear+1)%MAXSIZE==front | size==capacity |
| 最多存多少 | MAXSIZE-1 | capacity |
| 长度 | 循环距离 | size |
| 满时入队 | 失败 | 尝试扩容 |
| 下次写入下标 | rear | (front+size)%capacity |

“已用满当前容量”不意味着本动态队列一定无法入队；扩容成功后还可继续。
所有字段必须遵守初始化和接口维护的约定，不能随意手动改动。

size_t 是表示长度/下标的无符号整数类型，用 %zu 输出，不能保存 -1。

~~~c
Queue Q = {0};
if (!QueueInit(&Q, 4))
{
    return 1;
}
~~~

Q 是结构体，&Q 是结构体地址；Init 修改里面的 data/front/size/capacity。
不是 malloc 整个 Q，所以 Destroy 时不能 free(&Q)。
初始 {0} 很重要，避免读取未初始化指针。capacity 必须大于 0。

接口：

~~~c
int QueueInit(Queue *Q, size_t capacity);
int QueueEmpty(const Queue *Q);
size_t QueueLength(const Queue *Q);
int QueuePeek(const Queue *Q, ElemType *e);
~~~

查询均 O(1)。Peek 只读队头，不出队，输出参数必须有效且不能为 NULL。
失败不改输出值；只有成功后才能使用一个原本未初始化的输出变量。
NULL 不视为一个已初始化的空队列。

练习：容量 4、size=4 时还能使用多少空位？是否必须立刻让入队失败？

## 3. 入队与出队：移动下标，不移动所有元素

~~~c
int QueueEnqueue(Queue *Q, ElemType e);
int QueueDequeue(Queue *Q, ElemType *e);
~~~

入队前确保容量足够，写入逻辑尾部对应的物理下标，再 size++。
出队先检查非空，读取 data[front]，循环推进 front，再 size--。
e 可以为 NULL 表示出队但不取值。

队列末尾不一定对应数组末尾：

~~~text
capacity=4，front=2，size=4

物理下标：  0   1   2   3
数组内容：  5   6   3   4
逻辑顺序：  3 → 4 → 5 → 6
~~~

逻辑第 i 个元素的下标是 (front+i)%capacity。
实现中的 Index 用条件减法实现同样的环绕效果，避免极大下标的 front+i 溢出：

~~~c
size_t remaining = Q->capacity - Q->front;
if (offset < remaining)
{
    return Q->front + offset;
}
return offset - remaining;
~~~

前提是 offset<capacity、front<capacity。这是内部助手，不是供用户随意调用的接口。
普通复习先掌握取模公式，再读这段安全写法即可。

出队后不整体左移数组，所以 Dequeue 为 O(1)。
本版最后一个元素出队后主动把 front 重置为 0；考试版只要求 front==rear，不要求都为 0。

练习：上述逻辑队列出队一次得到什么？front、size 变成多少？

## 4. 扩容：按照逻辑顺序重新排列

~~~c
int QueueReserve(Queue *Q, size_t capacity);
int QueueEnqueueMany(Queue *Q, const ElemType a[], size_t n);
~~~

Reserve 是保证至少某个容量，不缩容、不改变元素数量。
如果容量够用，不搬迁也不强制把 front 变 0。
如果确实扩容，申请新数组，把逻辑第 0、1、2... 个元素依次复制到新下标 0、1、2...。

~~~text
扩容前：物理 [5 6 3 4]，front=2
扩容后：物理 [3 4 5 6 _ _ _ _]，front=0
逻辑顺序始终是 3、4、5、6
~~~

不能直接把整个旧数组按物理顺序复制，再把 front 改为 0；那会变成 5、6、3、4。

过程：检查容量字节数 → 申请 → 复制逻辑元素 → 释放旧数组 → 提交新地址与容量 → front=0。
申请失败时旧数组、front、size、capacity 全部不改。

自动入队通常倍增容量，检查 SIZE_MAX/sizeof(ElemType) 防止溢出。
单次扩容 O(n)，因此单次 Enqueue 最坏 O(n)；连续倍增入队均摊 O(1)。
出队不缩容，避免反复分配。

批量入队 a[0] 先入、a[n-1] 最后入：

~~~c
ElemType a[] = {10, 20, 30};
if (!QueueEnqueueMany(&Q, a, 3))
{
    QueueDestroy(&Q);
    return 1;
}
~~~

先一次保证容量，再写入全部元素；失败不只写入一部分。
n=0 允许 a=NULL。a 必须是外部有效数组，不能指向 Q.data 内部。
不要把“请求容量”误当成“新增长度”。

练习：为什么循环队列扩容比普通栈扩容多了逻辑顺序处理？

## 5. 清空、销毁与输出

~~~c
void QueueClear(Queue *Q);
void QueueDestroy(Queue *Q);
void QueuePrint(const Queue *Q);
~~~

Clear：front=size=0，保留数组，O(1)，可继续 Enqueue。
Destroy：释放 data，所有字段清零，O(1)，再次使用前要 Init。
Print：按队头到队尾打印，O(n)，不删除元素。

不要用 i=front; i<size 这种循环输出；size 是数量，不是尾下标。
输出参数必须指向队列外有效变量，防止删除时指向失效存储。

不能把 Queue B=Q 当成独立副本，两者共享数组，会造成重复释放或悬空访问。

### 最小模块调用示例

~~~c
#include "Queue.h"
#include <stdio.h>

int main(void)
{
    Queue Q = {0};
    if (!QueueInit(&Q, 2))
    {
        return 1;
    }
    if (!QueueEnqueue(&Q, 10) || !QueueEnqueue(&Q, 20))
    {
        QueueDestroy(&Q);
        return 1;
    }
    ElemType e;
    while (QueueDequeue(&Q, &e))
    {
        printf("%d\n", e);
    }
    QueueDestroy(&Q);
    return 0;
}
~~~

这个示例 main 需替换原 test.c 或另建独立目标，不要与原 test.c 一起链接。

## 6. 链队列：两个指针换来 O(1) 尾插

~~~c
typedef struct QueueNode
{
    ElemType data;
    struct QueueNode *next;
} QueueNode;

typedef struct
{
    QueueNode *front;
    QueueNode *rear;
    size_t size;
} LinkQueue;
~~~

不设置额外头结点：

~~~text
front → [10] → [20] → [30] → NULL
                         ↑
                        rear
~~~

链队列 front 指向首元素，rear 指向最后一个实际元素。
注意：考试循环队列的 rear 指向“下一次入队位置”，这里 rear 的含义不同。

空队列 front=rear=NULL；一个元素时 front==rear 且都不为 NULL。
缓存 size 后，求长无需遍历。

~~~c
int LinkQueueInit(LinkQueue *Q);
int LinkQueueEmpty(const LinkQueue *Q);
size_t LinkQueueLength(const LinkQueue *Q);
int LinkQueuePeek(const LinkQueue *Q, ElemType *e);
int LinkQueueEnqueue(LinkQueue *Q, ElemType e);
int LinkQueueDequeue(LinkQueue *Q, ElemType *e);
void LinkQueueClear(LinkQueue *Q);
void LinkQueueDestroy(LinkQueue *Q);
void LinkQueuePrint(const LinkQueue *Q);
~~~

先 LinkQueue L={0}，再 Init(&L)。不分配头结点，非空时重复 Init 返回失败。

入队：
申请新结点 p，设置 data 和 next=NULL；
原表为空则 front=p，否则旧 rear->next=p；
最后 rear=p、size++。

出队：
保存旧 front → 读取值 → front=旧 front->next；
如果 front 变 NULL，必须 rear=NULL；
然后 free 旧结点、size--。

忘记最后一个元素出队后重置 rear，会留下悬空尾指针；下次入队可能访问已释放内存。
保留 rear 让尾插为 O(1)，不必每次从 front 遍历到末尾。

链队列没有固定数组满的条件，但申请失败仍会入队失败，失败时原链不变。
Clear/Destroy 逐个释放结点，O(n)，在本实现中作用相同，都恢复可重用的空队列。
顺序队列 Clear 为 O(1)，链队列 Clear 为 O(n)，不要混淆。

## 7. 复杂度、应用与章节练习

| 操作 | 动态循环队列 | 链队列 |
| --- | --- | --- |
| 初始化、判空、求长、取队头 | O(1)，不计分配器内部成本 | O(1) |
| 入队 | 均摊 O(1)，单次最坏 O(n) | O(1)，不计分配器内部成本 |
| 出队 | O(1)，不整体移位 | O(1) |
| Reserve | 不搬迁 O(1)，搬迁 O(n) | 不需要 |
| 批量入 k 个 | 无扩容 O(k)，扩容 O(n+k) | 循环入队 O(k) |
| 清空 | O(1) | O(n) |
| 销毁 | O(1)，一次 free | O(n) |
| 输出 | O(n) | O(n) |

动态队列存储 O(capacity)，链队列存储 O(n) 且每个结点多一个指针。
扩容期间新旧数组同时存在，有 O(n) 级临时空间；其他普通操作辅助空间 O(1)。

应用：
BFS 按入队顺序逐层处理；树的层序遍历；消息、任务、数据缓冲。
本章为单线程队列，不是线程安全实现；生产者消费者的并发版本还需要同步机制。
双端队列允许两端都插删，本章普通队列不提供该接口，避免混淆。

### 总结与 C/C++ 对比

队列先进先出；循环数组靠下标绕回复用空间；链队列尾插头删并维护首尾。
动态扩容保持逻辑顺序；无头链队列最后一次出队必须同时清空 rear。

| C 本章 | C++ 后续 |
| --- | --- |
| struct + 独立函数 | class 封装 |
| 手动 Init/Destroy | 构造/析构、RAII |
| 固定 ElemType 为 int | 模板支持不同元素类型 |
| 自己维护队列 | std::queue，通常先 front 再 pop |
